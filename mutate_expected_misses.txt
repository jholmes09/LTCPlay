# Mutations that CI is expected to miss, and why. Read by
# `mutate.py --expected`, which fails the run on any miss NOT listed here, on
# any listed mutation that is now caught (so this list can only shrink), and on
# any SETUP FAIL.
#
# The "all" entries this list used to carry -- every mutation only a test
# that needs a whole real show could catch -- are gone: those tests
# (verify, the bundle, reload, the `at` timecode lookup, the read-only
# folder, the web page, and a couple more) now build a small generated show
# folder of their own (see test_show_fixtures.py) instead of skipping when
# LTCPLAY_TEST_SHOW_DIR is not set, so they run everywhere, including CI, and
# every one of those mutations is caught there too.
#
# What is left needs the actual GPL 2026 renders and xlights_networks.xml
# (600MB, never committed; CLAUDE.md), not a stand-in for them -- a check
# against the real show's own recorded audio names, frame counts or model
# layout, which a generated fixture cannot honestly claim to reproduce.
#
# Format: where | exact mutation name | reason
#   where is "all" (every OS) or "windows" (Windows only).

# -- macOS only
windows | the app runs from the wrong folder | only compiling and running the macOS C launcher catches it; that cannot run on Windows

# -- beyond.py: two guard layers by design (S5), so removing one alone is
# not independently observable while the other still refuses the same
# input the same way. Kept deliberately, not an untested gap: a future
# change that bypasses one layer still meets the other, which is the
# whole point of having both.
all | the allow-list no longer checks for OSC special characters | the exact-match check right after it already excludes every string that could contain one (BRIGHTNESS_ADDR itself has none), so no input exists today where removing this specific check changes the function's answer; kept as an explicit, self-documenting rule for a future BRIGHTNESS_ADDR that might not be so simple
all | _send()'s guard is removed, so anything can reach the socket | _Socket.send() enforces the identical allow-list one layer down and is never bypassed by this mutation, so every caller still sees the same refusal; test_beyond_lowest_level_socket_also_enforces_allow_list proves that lower layer directly
